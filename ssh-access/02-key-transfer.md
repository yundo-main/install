# 02 · 공개키를 노드로 전달

**요약.** [01](01-key-generation.md)에서 만든 `.pub` 파일을 노드로 옮긴다. 이
시점엔 아직 SSH 신뢰가 없어 스크립트로 자동화할 수 없다 — 부트스트랩 그
자체이기 때문이다. 개인키는 옮기지 않는다.

> **역할: 단계 문서 — 스크립트 없음.** 전달 방법이 노드 환경(네트워크 유무,
> 콘솔 접근 방식)에 따라 갈려 하나의 스크립트로 고정할 수 없다. `01`에서 만든
> `.pub` 을 [03-ssh-keys.md](03-ssh-keys.md)(노드 로컬)가 쓸 수 있는 위치에
> 올려놓는 것까지가 이 단계의 범위다.

| 항목 | 값 |
|---|---|
| **실행 위치** | Mac → 노드 (양쪽 콘솔을 오간다) |
| 전제 | [01-key-generation.md](01-key-generation.md) 로 만든 `.pub` 파일 |
| 결과 | 노드 파일시스템 위의 그 `.pub` 파일 사본 |

---

## 왜 스크립트가 없나

이 단계 이전에는 SSH·`scp` 경로가 없다 — 있었다면 애초에 이 절차 전체가 필요
없다. 전달 방법은 노드 환경에 따라 다음 중 하나를 쓴다.

| 방법 | 비고 |
|---|---|
| 콘솔 클립보드 붙여넣기 | 네트워크 유무와 무관 — 이 랩의 기본 경로 |
| VMware 공유 폴더 / USB | 네트워크가 없거나 클립보드 공유가 안 되는 노드 |
| `git clone` + 커밋 SHA 체크아웃 | `.pub` 을 리포에 커밋해뒀다면. **개인키는 절대 커밋하지 않는다** |
| `wget` raw URL | `.pub` 을 public 리포에 올려둔 경우만 — [00-ssh-server.md](00-ssh-server.md) 와 같은 공급망 신뢰 위험이 따른다 |

**콘솔 붙여넣기 예시:**

```bash
# Mac 에서 — 옮길 내용과 지문을 먼저 확인한다
cat ~/.ssh/lab_groom.pub
ssh-keygen -lf ~/.ssh/lab_groom.pub
```

```bash
# 노드 콘솔에서 — 위에서 확인한 한 줄을 그대로 붙여넣는다
cat > ~/lab_groom.pub <<'EOF'
ssh-ed25519 AAAA... lab_groom-202609
EOF
```

---

## 검증

노드에 도착한 파일의 지문이 Mac 에서 만든 것과 같은지 대조한다 — 오탈자·부분
붙여넣기로 깨진 키를 03(등록)으로 넘어가기 전에 여기서 잡는다.

```bash
# 노드에서
ssh-keygen -lf ~/lab_groom.pub
```

「왜 스크립트가 없나」에서 Mac 에서 확인한 지문과 문자 그대로 일치해야 한다.
다르면 [03-ssh-keys.md](03-ssh-keys.md) 로 넘어가지 않는다 — 다시 옮긴다.

---

## 잔여 위험 / 전제

- 콘솔 클립보드는 하이퍼바이저·터미널 앱의 스크롤백/클립보드 히스토리에 남을
  수 있다. 이 키가 그 정도로 노출돼도 되는 민감도인지 확인한다 (실습 키 전제).
- 붙여넣기 중 줄바꿈·공백이 깨지면 `authorized_keys` 형식이 무효화된다 — 위
  「검증」의 지문 대조를 반드시 거친 뒤 03 으로 넘어간다.
- `wget` 경로를 쓰면 그 리포·URL 이 공급망 신뢰 지점이 된다
  ([00-ssh-server.md](00-ssh-server.md) 의 같은 위험 참조).
- 이 문서는 `NN-<concept>.{sh,md}` 페어 규칙의 예외다 — 절차를 스크립트로
  고정할 수 없는 수동 단계이기 때문이다 (README.md 「명명 규칙」 참조).
