# install/ssh-access

VM 노드에 SSH 키 기반 접속을 구성하는 절차. Ubuntu 24.04 대상, 클라이언트는
macOS. 이 리포의 어떤 설치 대상이든 SSH 로 접근할 노드라면 공통으로 이 절차를
먼저 거친다 — 특정 설치 대상 전용이 아니라서 별도 디렉터리로 뒀다.

**실습용 구성.** 서버 설정(00)은 전 과정 수동이고, 키 생성·전달(01)은
비밀번호 인증을 부트스트랩 자격증명으로 쓰는 스크립트 지름길이다 — 보안·
재현성보다 절차를 손으로 익히는 쪽을 우선했다. 이유와 트레이드오프는 각
문서의 「잔여 위험」에 있다.

## 디렉터리 구조

```
install/ssh-access/
├── README.md                ← 현재 문서 — 인덱스·실행 순서·명명 규칙
│
├── 00-ssh-server.md          노드+Mac 수동: 서버 설정 + 첫 접속·지문 대조 (스크립트 없음)
├── 01-key-setup.md  / .sh    macOS: SSH 키페어 생성 + 노드로 전송
├── 02-ssh-keys.md   / .sh    노드 로컬: 공개키를 authorized_keys 에 등록
│
└── controls.md                고정한 통제·대조 상수·잔여 위험 색인
```

## 파일 역할

| 파일 | 역할 | 실행 위치 |
|---|---|---|
| [`00-ssh-server.md`](00-ssh-server.md) | sshd·ufw·인증 정책 구성 + Mac 첫 접속·호스트 지문 대조. **스크립트 없음, 전 과정 수동** | 노드 → Mac (절 앞에 표시) |
| [`01-key-setup.md`](01-key-setup.md) / [`.sh`](01-key-setup.sh) | SSH 키페어 생성 + `.pub` 전송. **비밀번호 인증 전제** — 꺼져 있으면 `--skip-transfer` 후 00 의 콘솔 절차로 수동 전송 | macOS 클라이언트 |
| [`02-ssh-keys.md`](02-ssh-keys.md) / [`.sh`](02-ssh-keys.sh) | 공개키 등록 (이 키를 신뢰한다) | 대상 노드 (로컬) |
| [`controls.md`](controls.md) | 통제 원칙·대조 상수·잔여 위험 색인 | (참조) |

`00`(정책)과 `02`(키 등록)을 분리한 이유: 정책은 노드마다 한 번 고정되지만 키는
회전·추가·폐기가 그보다 잦다. `01`(생성+전달)과 `02`(등록)을 분리한 이유는
신뢰 경계가 다르기 때문이다 — 개인키는 `01`을 실행한 Mac 을 벗어나지 않고,
`02`는 노드에 이미 도착한 공개키만 받는다.

## 명명 규칙

전 프로젝트 공통 정책은 [../readme.md](../readme.md) 「단계 문서 정책」 참조. 이
디렉터리에서의 적용:

- `NN-<concept>.{sh,md}` 페어, 같은 번호. 디렉터리 목록만 보고 실행 순서를 알 수
  있어야 한다.
- **예외**: `00-ssh-server.md` 는 `.sh` 가 없다 — 이 리포에서 유일하게 전 과정을
  스크립트 없이 수동으로 진행하는 단계다 (`docker/02-swarm-cluster.md` 와 같은
  범주의 예외).
- 각 `NN-<concept>.md` 는 H1 바로 아래에 `**요약.** …` 1~3문장을 둔다.
- 각 단계 문서는 자기완결이다 — 근거·실행·옵션·기대 출력·검증·잔여 위험을 한
  파일에 모은다. 코드가 문서와 어긋나면 문서가 기준이다.

## 실행 순서

| # | 실행 위치 | 문서 |
|---|---|---|
| 00 | 노드 콘솔 → Mac (문서 안에서 전환) | [00-ssh-server.md](00-ssh-server.md) |
| 01 | macOS 클라이언트 | [01-key-setup.md](01-key-setup.md) |
| 02 | 대상 노드 (콘솔/로컬) | [02-ssh-keys.md](02-ssh-keys.md) |

재확인은 `01-key-setup.sh`/`02-ssh-keys.sh` 의 `--verify-only`. `00`은 스크립트가
없어 문서의 각 절 명령을 그대로 따라 재확인한다.

## 스크립트 분리 기준

**실행 주체의 신뢰 경계가 다르면 파일을 나눈다.** 노드 로컬(`02`)과 macOS
클라이언트(`01`)를 한 파일에 두지 않는다. 노드로 전송되는 스크립트(`02`)는
클라이언트 로직을 포함하지 않고, 외부 파일을 참조하지 않는 자기완결
스크립트여야 한다. `00`은 스크립트가 아니라 문서이지만, 문서 안에서도 노드
절과 Mac 절을 명확히 나눠 표시한다(「실행 위치가 문서 안에서 바뀔 때」 규칙,
[../readme.md](../readme.md) 참조).
